# 硬编接入实验台（Encoder Lab）

一个可运行的硬件视频编码接入原型：程序自己生成帧，按设备的真实要求建立图像表面
（颜色格式 / 平面步幅 / 有效尺寸都做真实转换），提交给编码接口，异步取回码流并用
独立解码器还原画面逐帧核对。仓库同时带一个软件对照后端（OpenH264），在没有硬件
编码节点的主机上也能跑通并演示同一套接口语义；它不会被包装成硬件测量。

## 1. 构建

依赖：C++17 编译器、GNU make、zlib 开发文件。OpenH264 2.4.1 已随仓库提供
（`third_party/openh264/`，含 `LICENSE` 与 `BUILD_INFO.txt`），无需联网。

```sh
make
```

产物是 `build/encoder_lab`。

## 2. 启动界面

```sh
./build/encoder_lab --port 8099
```

然后在浏览器打开：

```
http://127.0.0.1:8099/
```

可选参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--host` | `127.0.0.1` | 监听地址；只在本机使用时保持默认 |
| `--port` | `8099` | 监听端口 |
| `--web` | `web` | 静态界面目录 |

服务启动后，界面由硬编接入内核（`Session`）的状态驱动：可用的编码后端、协商后的
表面格式、当前送帧方式的能力与限制都来自后端探测结果，而不是写死在页面里。运行
结束后按 `Ctrl-C` 退出（会先停止正在运行的任务并回收资源）。

## 3. 在界面上做什么

1. 选择 **编码后端**：`OpenH264 软件对照（接口模型）` 或探测到的 V4L2 M2M 节点
   （若本机没有硬件节点，下拉列表里只有软件对照，并在上方明确标注硬件未覆盖）。
2. 选择 **送帧方式**，点「开始运行」：

   | 方式 | 演示的接口语义 |
   | --- | --- |
   | `paced` | 按帧率节流，正常完成回执与回收 |
   | `burst` | 不节流，尽快提交，观察有限池上的背压 |
   | `late` | 延迟完成回执，表面在码流可取后仍保持不可写，直到回执才复用 |
   | `guard` | 所有权守卫：对仍可能被硬件读取的表面尝试写入会被拒绝并计数 |
   | `corrupt` | 注入一次表面内容损坏，验证解码核对能检出而不是静默通过 |
   | `earlyreuse` | 提前复用：输出包已可读、输入表面仍未获准回收时强行改写，解码画面留下可识别串帧 |

3. 选择 **表面调度器**：`固定池` 不扩缩；`弹性扩缩` 按归还反馈在 `[池下限, 池上限]`
   内增长/收缩（规则见第 7 节）。`读延迟/扫描时长` 是软件模型的可控回调，用来构造
   “输出包已可读、输入表面仍在被读取”的交错。
4. **事件门**：勾选「单步放行」后，产包/归还事件不再自动生效，需要在「事件门」
   面板逐个点放（步进·产包 / 步进·归还 / 步进·任意 / 继续放行）；「事件顺序」
   可让自动模式偏好先放产包或先放归还；「重放脚本」填入一串 `p`/`r` 可逐事件复跑
   某次故障调度。面板里的「调度轨迹」记录本次实际放行顺序，「重放此调度」一键把它
   填回脚本再跑，「A/B 轨迹对照」按两种偏好各跑一次并对比内存峰值、阻塞与错误角标。
5. **分辨率切换**：填「切换帧号」后，旧分辨率的编码代次继续排空，新分辨率代次立即
   建池送帧；两代次的表面在「表面状态」区按代次分组展示，旧代次的一次归还恰好晚于
   新池分配出同号表面时会被识别并隔离（见第 9 节）。
6. **结果区**并排显示源画面与解码输出，并给出三个相互独立、绝不合并的判定标签：

   * `会话创建` —— 编码会话是否创建成功；
   * `链路` —— 每个提交帧是否都产出码流、解码画面在帧号 / 参考色块 / 颜色 / 内容上
     是否与源一致、所有表面是否归还；
   * `硬件覆盖` —— 本次是否真的跑在硬件编码器上；软件对照会明确写成未覆盖。

   另有一个独立的 `时序` 标签：`设备实测` 仅当数据来自真实 V4L2 设备；软件后端的
   一切时序（回执延迟、读延迟、扫描时长）都标记为 `软件模型模拟`，界面与报告不会
   把模拟测得的数字写成来自真实编码的结论。

7. **表面状态** 区按代次分组显示每个表面（含索引、状态 FREE/FILLING/QUEUED/RETIRED、
   当前帧号、复用次数、填充次数、实际协商出的格式 / 可见尺寸 / 编码尺寸 / 步幅、
   释放条件）。表面池是有限的：在途数量受池大小约束，不需要靠无限分配掩盖回收问题。
8. **帧号 / 顺序 / 回执** 表逐帧列出状态、代次、所用表面、码流大小、标记期望/实际、
   **四角角标**（逐帧唯一，提前复用会让同一帧的四个角读出不同帧号，表中红显“串帧”）、
   色块与颜色核对、MAE、提交→码流、提交→可复用两个时延，以及异常说明。
9. **运行指标** 包含提交/码流/核对计数、乱序与重复、背压等待次数与累计时间、最大在途
   表面、弹性调度的增长/收缩/等待计数、峰值活跃表面与峰值映射字节、错误角标与串帧数、
   越权写入、跨代次迟到归还、未归还表面、EOS 排空状态、RSS 基线与峰值、时延分位数。
   结果区下方同时给出 **容量建议**（由本次归还滞后分布推算的固定池容量，见第 7 节）。

界面每 250 ms 轮询一次 `/api/state`；页面本身不持有运行状态，刷新不会丢失结果。

## 4. 无浏览器自检

用于 CI 或远程主机上验证整条链路：

```sh
./build/encoder_lab --selftest openh264            # 默认 paced
./build/encoder_lab --selftest openh264 --mode late
./build/encoder_lab --selftest openh264 --mode earlyreuse   # 提前复用→串帧检出
./build/encoder_lab --selftest openh264 --mode late --sched elastic --poolmin 2 --poolmax 6
./build/encoder_lab --selftest openh264 --scenario switch   # 分辨率切换+代次隔离
./build/encoder_lab --selftest openh264 --scenario replay   # 记录轨迹并逐事件重放
./build/encoder_lab --selftest openh264 --scenario ab --mode late  # 两条轨迹对照
./build/encoder_lab --selftest v4l2                # 无硬件时诚实 FAIL
```

其余自检参数：`--sched fixed|elastic`、`--pool N`、`--poolmin N`、`--poolmax N`、
`--order any|packet|return`、`--script prpr...`、`--readdelay ms`、`--scan ms`。

自检会打印中文报告（提交/码流数、帧号核对、背压、最大在途、未归还表面、EOS、
RSS、时延），最后一行是 `RESULT : PASS` 或 `RESULT : FAIL`，退出码 0/1。

在没有匹配的 V4L2 M2M H.264 编码节点时，v4l2 自检会明确报告「未找到设备、不报告
任何硬件吞吐数据」并返回 FAIL —— 这是覆盖缺口，而不是被软件结果掩盖的通过。

## 6. 硬件接入说明（V4L2 M2M）

`src/encoder_v4l2.cpp` 走标准的 V4L2 内存到内存接口：`QUERYCAP` → `ENUM_FMT` →
`S_FMT/G_FMT`（尊重驱动实际授予的编码尺寸与 `bytesperline`）→ `REQBUFS/QUERYBUF/mmap`
→ `QBUF/DQBUF` 双队列 → `STREAMON` → `VIDIOC_ENCODER_CMD(V4L2_ENC_CMD_STOP)` 排空 →
`V4L2_BUF_FLAG_LAST` → `STREAMOFF` 与 `munmap`。同时支持单平面与多平面（`_MPLANE`）
节点，并把驱动返回的时间戳映射回帧号（无时间戳复制时按 FIFO 顺序回退并记录说明）。

当前环境没有可用的硬件编码节点，因此仓库内没有、也不会提供任何硬件测速数据。有
设备时，界面会把该节点列入后端下拉框，`硬件覆盖` 标签才会变绿。

## 7. 表面调度器：固定池与弹性扩缩

实验台提供两种表面调度器（`src/scheduler.h`），通过 `sched=fixed|elastic` 选择：

* **固定池**：池大小不变，没有空闲表面就只能等归还。用来暴露背压与容量不足。
* **弹性扩缩**：按归还反馈在 `[poolMin, poolMax]` 内调整活跃表面数。

弹性规则是轨迹实验（`--scenario ab` / `--scenario replay`）选定的：

* **何时增长**：没有空闲表面、池未到上限，且最旧在途表面的预计归还等待超过
  **半个帧周期** 时才增长；没有在途表面可等时立即增长。更早增长只是租用稳态
  用不到的内存，更晚增长会让送帧循环误帧。
* **何时等待**：归还预计在半帧预算内到达时，等待比租新内存便宜（会计入
  `schedWaits`）。
* **何时收缩**：某表面连续空闲满 **8 个帧周期**、且空闲表面 ≥ 2、池高于下限时，
  退休一个表面。

软件后端的增长/收缩是真实的主机内存分配/释放；V4L2 后端受 REQBUFS 语义约束，
建池时按 `max(pool, poolMax)` 预留缓冲，增长=激活一个已预留的未映射缓冲，
收缩=把表面标记退休（缓冲保持映射，不伪造 REQBUFS 重协商）。

**容量选择依据**：报告末尾的「容量建议」由本次运行的归还滞后分布给出——
`k = ceil(p50(提交→可复用) / 帧周期)`，稳态在途约 `k` 个表面，固定池容量建议
`≥ k+1`。例如 late 模式 120 ms 回执、30 fps 时 k=4，建议 ≥5；实测固定池 3 会
阻塞 27 次 / 约 900 ms，弹性池从 3 增长到 4 后阻塞归零。

**轨迹对照与可复跑调度**：`--scenario ab` 用同一负载分别按「产包事件优先」与
「归还事件优先」跑两遍，对照内存峰值（RSS 与映射字节）、阻塞次数/时长、错误
角标/串帧；`--scenario replay` 先记录一条轨迹再按脚本逐事件重放，两次轨迹必须
完全一致。每次运行的轨迹字符串都在报告与界面「调度轨迹」中，可复制为 `--script`
或「重放脚本」复跑同一次故障调度。

## 8. 交错构造与角标串帧

**输出包已可读、输入表面仍未获准回收**：软件后端把一次提交建模为——提交后
`readDelayMs` 开始分 8 条带扫描表面（耗时 `scanMs`）到暂存缓冲，扫描完成即产出
码流包，而表面要到 `receiptLagMs` 才归还。码流可读与表面可复用之间的窗口是真实
存在的所有权禁区；V4L2 后端则天然如此（DQBUF(CAPTURE) 先于 DQBUF(OUTPUT)）。

**逐帧角标**：每帧在四个角写入 12 bit 帧号（6×2 位块），解码后独立读回。四个角
读出不同帧号 = 同一画面混入了两个帧的内容，即**可识别的串帧**。

**提前复用（earlyreuse）**：送帧循环在受害帧扫描中途（提交后 readDelay+scan/2）
强行把下一帧内容写进仍在被读取的表面。结果：码流包照常产生、帧号标记照常正确，
但上半部分角标是旧帧、下半部分是下一帧——只有逐角核对才能识别。该帧被判定为
「检出」而不是「失败」，因为链路忠实地把一次所有权违规呈现成了可观测证据。

缺少设备时，上述所有权语义全部通过软件模型的**可控回调**（提交/扫描/归还三个
定时点）测试；界面与报告把所有由此测得的时序标记为「软件模型模拟」。

## 9. 分辨率切换与代次隔离

`switchAt=N` 时，第 N 帧起用新分辨率创建**新代次**（新编码会话、新表面池、新
解码器），旧代次继续排空直到 EOS。两代次的表面池短暂共存，「峰值映射字节」会
如实反映这段叠加。

归还事件按代次路由：旧代次某表面的归还晚于新池分配出**同号**表面时，只记
`staleGenReleases` 并作用于旧代次账本，绝不会把新池的同号表面错误释放。旧代次
的所有表面归还都**实际确认**（事件经事件门生效）后，旧代次资源才销毁——界面
「代次」卡片可看到旧代次从 `draining` 到 `done`（表面数归零）的全过程。

## 11. 已知限制

* 本环境没有硬件编码节点，`encoder_v4l2.cpp` 的代码路径无法在此实测；它按标准
  V4L2 M2M 语义编写，但未在本机设备上验证过。界面与自检会明确标为「硬件未覆盖」。
* 软件对照后端是 OpenH264，它的“延迟回执 / 读延迟 / 分条扫描”是按接口模型模拟的
  （码流同步可得、表面在回执时刻才释放），用于演示回收与所有权语义，不代表任何
  硬件的时延或吞吐；所有时序结论都带「软件模型模拟」标记。
* V4L2 后端在驱动不回报时间戳时按 FIFO 顺序把输出映射回帧号，并在日志中说明；
  若驱动乱序返回且不支持时间戳复制，帧号映射会不准确，这一点不会被静默忽略。
* 单步/脚本模式下，事件放行由人（或脚本）控制，运行期间的阻塞时长统计不代表
  自动模式下的真实等待；容量建议会注明这一点。

## 12. 测试

```sh
scripts/smoke.sh        # 构建 + 全部送帧方式、弹性扩缩、切换、重放、A/B 自检
scripts/api_test.sh     # 启动服务，经 HTTP 验证完整运行、单步门与轨迹重放
```

`smoke.sh` 对每种方式断言 `RESULT : PASS`，并额外断言：`guard` 拒绝计数 ≥ 1；
`corrupt` 恰好检出 1 帧；`earlyreuse` 恰好 1 次越权写入 + 1 帧串帧；弹性 late
增长 ≥ 1 且阻塞归零；弹性 paced 收缩 ≥ 1；`switch` 跨代次迟到归还 ≥ 1；`replay`
两次轨迹一致。`api_test.sh` 校验：会话创建、逐帧码流、解码核对、零未归还表面、
EOS 完成、单步门拦住事件→步进 4 次轨迹长 4→继续放行跑完、同脚本重放轨迹一致、
时序来源标记为模拟，以及 `/api/frame.png`、`/api/au` 可实际取到数据。
